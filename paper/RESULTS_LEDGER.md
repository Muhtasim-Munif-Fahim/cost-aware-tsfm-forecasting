# Results Ledger

Every quantitative claim that will appear in the manuscript must have a row here before it is
written into any section file. The manuscript references rows via `<!-- L-### -->` HTML comments;
Phase 7's number-audit subagent mechanically joins draft claims → this ledger → the artifact on
disk, recomputing each value independently. A claim with no row, or a row whose recomputed value
doesn't match, blocks submission.

Analysis scripts (Phase 3, under `analysis/`) append stub rows automatically when they run; the
`claim` and `paper location` columns are filled in by hand once the prose is written (Phase 6).

## Columns

- **ledger_id** — `L-###`, monotonically assigned, never reused.
- **claim** — the plain-English statement this number supports (fill at Phase 6).
- **value** — the actual number/stat (with units).
- **paper location** — section + item (e.g. "Results §3.1, Table 1"); filled at Phase 6.
- **artifact** — path to the CSV/file containing the value.
- **producing command** — exact CLI invocation that generated the artifact.
- **run_id** — `R###` from `results/v1/RUNS.csv`.
- **code tag** — git tag/commit the run was executed under.
- **input sha256** — reference into `data/manifest.sha256` (or "n/a" for a derived/analysis artifact).
- **date** — run date.
- **verified** — who/what last verified this row (e.g. "Phase 3 script", "Phase 7 audit subagent").
